# Architecture Decisions

## ADR-0001：设备身份与网络地址分离

设备使用稳定 `DeviceID`；IP、MAC 和接口状态仅作为观测数据。原因是 DHCP、Wi-Fi 漫游和多网卡会改变地址。

## ADR-0002：发现不授予权限

发现只生成待配对设备。加入课堂必须经过短码/二维码、预注册或教师审批，并创建可撤销的成员关系。

## ADR-0003：Service 与 User Agent 分离

Windows Service 承担特权、策略和网络职责；User Agent 承担交互会话和 UI。两者通过受保护的本机 IPC 通信。

## ADR-0004：批量操作使用结果聚合

一个命令可针对组或课堂，但每个目标都产生独立结果；请求具备幂等键、截止时间和重试策略。

## ADR-0005：控制面与数据面分离

命令、状态和审计使用可靠控制通道；屏幕、音频和视频使用独立数据通道。数据面拥塞、编码失败或断流不能阻塞锁屏、撤销授权和命令结果。

## ADR-0006：SQLite 作为本地事实源

课堂成员、授权、命令和审计写入 SQLite；发现和心跳作为可重建缓存。这样互联网断开和进程重启不会丢失课堂边界，同时避免把高频网络观测当作永久历史。

## ADR-0007：网络模式隐藏在端口后

P2P、Teacher Controller 和 Classroom Server 共享应用层契约。模式差异只存在于 discovery、session 和 transport adapter，避免为每种拓扑复制授权和命令逻辑。

## ADR-0008：不在 Phase 0 落盘屏幕帧

屏幕流默认只在内存中传输。录屏、截图和文件收集作为显式授权的后续能力，拥有独立的数据保留、加密和审计策略。
